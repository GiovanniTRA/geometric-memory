# Geometric Memory in Knowledge Editing

Minimal reference implementation of the main result in **"Position Paper: LLM Model
Editing Has a Geometry Problem"**: ROME on LLaMA-3.1-8B, scored with GIS_theta
(geometric) and GIS_acc (behavioral), over the paper's 100-edit, 8-domain benchmark.

| Metric | Description |
|---|---|
| `nGIS_theta` | `>0` edit improved geometric inheritance, `0` no change. |
| `GIS_acc` | Soft accuracy on 10 entity-specific A/B questions. `delta_gis_acc` is the change from unedited to edited target. |

Ships one method (ROME) and one model (LLaMA-3.1-8B). See the paper for the full
comparison (5 models x 5 methods + AlphaEdit).

## Install

```bash
pip install -r requirements.txt
```

`meta-llama/Llama-3.1-8B` is gated on the Hugging Face Hub -- request access and
`huggingface-cli login` first.

## Run

```bash
python extract.py            # once: pre-edit embeddings for all 8 domains
python run_edit.py 0         # a single edit (index 0-99)
python run_all.py            # all 100
python run_all.py --limit 5  # smoke test
python stats.py              # aggregate results/*.json
```

Each edit writes `results/gis_edit_N.json` and `results/gis_acc_edit_N.json`.
Embeddings and results aren't shipped -- regenerated by running the code.

## Dataset

- [config.py](config.py) -- `EDIT_TABLE` (the 100 edits), `DOMAINS` (reference
  entity sets), `TEMPLATES` (context sentences for embedding extraction).
- [data/entity_questions.json](data/entity_questions.json) -- 10 A/B questions
  per edit for GIS_acc.
