# Geometric Memory in Knowledge Editing

Minimal reference implementation of the main result in **"Position Paper: LLM Model
Editing Has a Geometry Problem"**: ROME on LLaMA-3.1-8B, scored with GIS_theta and
GIS_acc, over the paper's 100-edit, 8-domain benchmark.

Given a factual edit (e.g. *"The capital of France"* &rarr; *"TucuTucu"*), geometric
inheritance asks whether the edited model's representation of the new entity ends up
"living in the right neighborhood" of the embedding space -- geometrically close to
where the old entity used to sit relative to related entities -- not just whether the
model generates the right token.

| Metric | Description |
|---|---|
| `nGIS_theta` | Normalized geometric inheritance score. `>0` means the edit improved geometric inheritance relative to the pre-edit baseline; `0` is no change. |
| `GIS_acc` | Soft accuracy on 10 entity-specific factual A/B questions, scored on the unedited source, the unedited target, and the edited target. `delta_gis_acc` is the change from unedited to edited target. |

The paper's finding, reproduced here at small scale: `nGIS_theta` and `delta_gis_acc`
sit close to zero even when the edit itself succeeds (the model happily generates the
new target) -- the edit changes what the model *says* without moving the target's
*representation* into the geometric neighborhood the source used to occupy.

This repo intentionally ships **one method (ROME) and one model (LLaMA-3.1-8B)** --
the paper's own full results (5 models x 5 methods, plus AlphaEdit) are not reproduced
here. See the paper for the complete comparison.

## Installation

```bash
pip install -r requirements.txt
```

Tested with Python 3.14, PyTorch 2.12, Transformers 5.6. Requires a CUDA GPU with
enough memory to hold LLaMA-3.1-8B in float16 (~16GB) plus activations; a single
24GB+ GPU is sufficient. `meta-llama/Llama-3.1-8B` is a gated model on the Hugging
Face Hub -- request access and run `huggingface-cli login` before the first run.

## Running

```bash
# once: pre-edit embeddings for all 8 domains (~10-15 min)
python extract.py

# a single edit (index 0-99)
python run_edit.py 0

# all 100 edits, one fresh subprocess per edit (see "Determinism" below)
python run_all.py

# smoke test: first 5 edits only
python run_all.py --limit 5

# aggregate results/*.json into the summary table
python stats.py
```

Each edit writes `results/gis_edit_N.json` (GIS_theta + the raw cosine-similarity
profiles it's computed from) and `results/gis_acc_edit_N.json` (GIS_acc, with
per-question detail). Pre/post-edit embeddings and `results/` are regenerated by
running the code above -- not shipped in this repo.

## Determinism

ROME's context-template sampling (`easyedit/models/rome/rome_main.py:get_context_templates`)
draws from the model via unseeded sampling and caches the result in a module-level
global, populated once per process. `run_all.py` runs each edit in its own fresh
subprocess so no edit's result depends on another's, but re-running `run_edit.py`
for the *same* edit index in two different processes can land on a different template
draw and produce a measurably different result (we've observed single-edit swings on
the order of 0.05-0.1 in `nGIS_theta` from this alone). This is a property of the
upstream ROME implementation, not of GIS or this repo's measurement code.

## Dataset

- [config.py](config.py) -- `EDIT_TABLE`: the 100 edits (source entity, fictional
  target entity, edit prompt, domain, cluster). `DOMAINS`: each domain's reference
  entity set, which GIS_theta measures distance to. `TEMPLATES`: the 8 context
  sentences embeddings are extracted from and averaged over.
- [data/entity_questions.json](data/entity_questions.json) -- 10 entity-specific A/B
  questions per edit for GIS_acc. Each question pairs a true fact about the *source*
  entity against a plausible same-domain distractor, so a correct answer requires
  entity-specific transfer, not generic domain plausibility.

## What's vendored, and what's deliberately left out

[easyedit/](easyedit/) is a trimmed copy of ROME from
[EasyEdit](https://github.com/zjunlp/EasyEdit) (MIT-licensed, kept under
[easyedit/LICENSE](easyedit/LICENSE)) -- only the files ROME's default configuration
actually exercises. In particular, `easyedit/models/rome/layer_stats.py` is a stub:
the hyperparameters here set `mom2_adjustment: false`, so the full covariance-
statistics collector (and the `datasets`/`tqdm` dependencies it would need) is never
called; see that file's docstring.
